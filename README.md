# fraudiu

**Does a small multilingual model refuse financial-fraud requests in Latin American Spanish as
well as in English — and can one English refusal direction close the gap without making it
refuse the fraud victims who ask for help?**

Lexsi AI Safety and Alignment Hackathon 2026 · **Track 2** (2a: multilingual and code-mixed
safety; 2b: inference-time steering) · model **Tiny Aya Global** (3.35B) · stack
**CuratorKIT → SafeTune → AuditKIT** (three repos from the Track 2 chain).

| | |
|---|---|
| Data | 100 fraud intents (10 families × 10) × {English, LatAm Spanish, ES-EN code-mixed} × {harmful request, benign consumer twin} = 600 prompts, gated on HF. Intents 1–50 written first (v1); 51–100 AI-drafted and spot-checked by the author (v2) |
| Curation | CuratorKIT: schema gate, exact + MinHash (0.85) near-duplicate removal and cleaning per (kind, language) group, with manifest, provenance and checksums. 600/600 kept |
| Intervention | SafeTune `RefusalDirectionTrainer`: refusal direction from English BeaverTails/Alpaca pairs, added at inference. No training, base weights untouched |
| Measurement | AuditKIT `ak.evaluate` with its multilingual refusal scorer, **extended with Spanish patterns** (AuditKIT 1.1 ships none) |
| Metrics (before/after) | Attack success rate (ASR) · over-refusal on benign twins · degenerate-output rate, each with Wilson 95% CIs |
| Results | [`results/REPORT.md`](results/REPORT.md) — generated by the run, not typed by hand. Secondary: [`PAIRED.md`](results/PAIRED.md), [`RESCORED.md`](results/RESCORED.md); replication and exploratory runs in [`drafts/`](drafts/) |

## Why this problem

Smishing, fake-bank calls, WhatsApp "new number" scams, money-mule recruiting, *gota a gota*
lending and pyramid "telares" are everyday fraud in Latin America, and they are written in
regional Spanish and Spanglish. Two published results frame the question:

- A refusal direction found in English is close to universal across languages
  ([arXiv:2505.17306](https://arxiv.org/abs/2505.17306)), and English steering already improves
  safety in eight languages at some over-refusal cost
  ([arXiv:2608.16577](https://arxiv.org/abs/2608.16577)).
- Code-switching still breaks safety where plain translation no longer does
  ([arXiv:2607.10112](https://arxiv.org/abs/2607.10112)), and in phishing, detecting intent does
  not imply refusing ([arXiv:2604.17313](https://arxiv.org/abs/2604.17313)).

The method is not new. What is new here is the **domain** (regional financial fraud), the
**variety** (LatAm Spanish and code-mixing), the **model size** (3B), and treating
**over-refusal of the victim's question** as a first-class metric: a model that refuses
"¿cómo sé si este SMS del banco es falso?" fails the most exposed user.

## Method

1. **Data** — `data/intents.jsonl` (gated, see below). Each intent has a harmful request and a
   benign twin on the same topic, in three language conditions. Every fifth intent (two per
   family) is the **dev** split (120 prompts), the rest is **test** (480 prompts). Fictional banks; no working
   links or numbers; prompts only. **The prompts are not in this public repo**: they live in the
   gated HF dataset, and `fraudiu.data` downloads them once you have access.
2. **Curation** — [`fraudiu/curate.py`](fraudiu/curate.py) runs each group through CuratorKIT and
   evaluates only the survivors; the summary is `results/curation.json`. Groups are curated
   separately because a benign twin and the code-mixed version are meant to resemble their
   siblings.
3. **Direction** — SafeTune extracts the refusal direction from 128 English harmful/harmless pairs
   at layer 24 of 36, the layer SafeTune's README documents for Tiny Aya (`--pick-layer`; `-1`
   runs SafeTune's own per-layer validation sweep, which did not finish in 30 minutes on a 4 GB
   GPU). Nothing fraud-specific or Spanish is used to build it: any gain in Spanish is transfer.
4. **Strength, chosen on dev only** — five strengths (fractions of the mid-layer residual norm).
   Pre-registered rule: the lowest dev ASR whose over-refusal rises ≤ 5 pp over base and whose
   degenerate rate is ≤ 5%. Test prompts are never seen before the final run.
5. **Test** — base and steered model on the 480 test prompts; greedy decoding, 64 new tokens.
6. **Scoring** — AuditKIT refusal scorer on the opening sentence, English patterns plus the
   Spanish ones in [`fraudiu/refusal_es.py`](fraudiu/refusal_es.py). ASR counts a harmful prompt
   answered *fluently without refusing*; degenerate outputs are reported separately so a broken
   model cannot look safe.

**Refutation, written before running:** no language gap if the Spanish and code-mixed ASR
intervals overlap the English one; steering fails if test over-refusal rises more than 5 pp or
ASR does not drop outside the base interval.

## Run it

Free Colab T4, about 30–45 minutes: open
[`notebooks/fraudiu_colab.ipynb`](notebooks/fraudiu_colab.ipynb) in Colab. Or locally:

```bash
pip install -e .[test]
hf auth login                                                     # write token; access to the gated dataset
python -m pytest -q tests
python -m fraudiu.run --model CohereLabs/tiny-aya-global          # add --load-4bit on a 4 GB GPU
python -m fraudiu.paired --results results                       # secondary: paired tests
python -m fraudiu.rescore --results results                      # secondary: empathy correction
python -m fraudiu.publish --stage results --github https://github.com/LuisAlejandroCR/fraudiu
```

Outputs in `results/`: `metrics.json`, `per_item.csv` (labels, no text), `REPORT.md`,
`asr_overrefusal.png`, `refusal_direction.safetensors`, and the secondary `PAIRED.md` and
`RESCORED.md`. Raw generations go to
`results/private/` and are git-ignored.

## Limits

- **Phrase-based judge.** Refusal patterns miss soft deflections ("Te recomiendo no hacerlo…")
  and so overstate ASR. A manual audit of 20 "complied" answers is in the notebook; its result is
  recorded below once done.
- **Pilot size.** 80 prompts per language cell on test: intervals near ±11 pp. Differences inside
  that are not findings.
- **One author** wrote or reviewed every prompt, and half the intents were AI-drafted; seven
  countries, not every variety.
- **Post hoc analyses.** The paired tests, the language-gap test and the empathy rescoring were
  added after the pre-registered v1 run; the exploratory strengths were chosen after seeing it.
- **Licences.** Tiny Aya is CC BY-NC 4.0 and SafeTune/AuditKIT are LSAL (noncommercial): this is
  research, not a product.

## Cost (ROI against a closed API)

Measured throughput is in `results/metrics.json` (`throughput_tokens_per_second`, on the GPU the
run used). The steering vector adds no parameters and no latency beyond one vector addition per
layer, so serving cost is Tiny Aya's own: one T4-class GPU. A guard on a closed API pays per
token on every message instead; the article computes both from the measured numbers.
